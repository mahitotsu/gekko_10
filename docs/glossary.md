# 用語集

**この文書の読み手:** 文書に出てくる用語や略語、構成名の意味を、確かめたい人。

文書では、初出でこの用語集にリンクするか、ここの呼び名を使う。

## 比べているもの
| 用語 | 意味 |
|---|---|
| Event | 関数URL で公開する通常の Lambda 関数（Event Functions）。1 つの実行環境が、同時に 1 つのリクエストだけを処理する |
| Web | Lambda Web Functions。HTTP サーバーをそのまま動かし、1 つの実行環境が、複数のリクエストを同時に処理する（この検証の設定では最大 64） |
| 実行環境（環境） | 関数のコードを動かしている 1 つの単位。リクエストが増えると、Lambda が環境を増やす |
| コールドスタート | 新しい環境を作って、最初のリクエストを処理すること。初期化のぶん遅くなる |
| DSQL | Aurora DSQL。どちらの関数も、データの読み書きに使う |
| 接続プール（プール） | データベースへの接続を使い回すための仕組み。Web の環境は、プールを共有する |
| プール上限 | プールが同時に持てる接続の最大数。上限を超えた要求は、空きが出るまで待つ |

## 構成名と、文書での呼び名
コード・結果のファイルでの名前（構成名）と、文書で使う呼び名の対応。文書の本文では、呼び名を使う。

| 構成名 | 呼び名 | 内容 |
|---|---|---|
| `event-dsql-reuse` | Event | Event。環境ごとに DSQL への接続を 1 本持ち、使い回す |
| `web-dsql-pool10` | Web（プール 10） | Web。環境ごとのプール上限が 10（一般的な既定値） |
| `web-dsql-pool` | Web（プール 64） | Web。環境ごとのプール上限が 64（待ちが起きにくい対照） |

## 測定のケース
実際のアプリの使い方に近い 4 つの負荷。定義は [plan.md](plan.md)。

| ケース | 呼び名 | 内容 |
|---|---|---|
| A | 外部 I/O を挟む API | 外部 API の応答を 1 秒待つ処理（DB の読み書きではさむ） |
| B | 混在した一般的な API | 軽い読み取りが 7 割。N+1 の画面、重い集計、CPU 処理、書き込みが混ざる |
| C | 急なスパイク | 毎秒 10 件から、毎秒 1,500 件に急に増える（2 回） |
| D | 重い集計が主 | 約 250 ms の集計だけが続く |

## 負荷と指標
| 用語 | 意味 |
|---|---|
| RPS | 1 秒あたりのリクエスト数 |
| 段 | 一定の RPS で一定時間（45〜90 秒）かける 1 区間 |
| 回 | 1 つの構成に 1 つのケースを、段を順に上げて流す 1 回の実行 |
| セット | 全ての回を 1 巡する単位。1 セット目はウォームアップで捨て、2・3 セット目を使う |
| 同時実行数 | 同時に処理中のリクエストの数。おおよそ「RPS × 応答時間」。Event では環境の数とほぼ同じ |
| p50、p99 | 応答時間の中央値、遅い方から 1% の境目（99% の要求がこの時間以内に終わる）。どちらもクライアントで測った時間 |
| アプリ内の時間 | 関数のコードが処理に使った時間（応答の `appMs`）。DB の時間を含む |
| 経路の時間 | クライアントで測った応答時間から、アプリ内の時間を引いたもの。ネットワーク、入口の処理、関数の呼び出しにかかる時間（以前の文書では「アプリの外」） |
| DPU | DSQL の処理量の単位。課金の単位でもある（東京で 1 DPU あたり $0.00001） |
| OCC | 楽観的な同時実行制御。同じ行を同時に書くと、片方が競合で失敗する。DSQL の書き込みの競合は、これで起きる |

## 費用と信頼性
| 用語 | 意味 |
|---|---|
| 定価 | 無料枠を考えずに、公表の単価を掛けた金額。Event と Web の比較は、定価で行う |
| 実際の請求 | 無料枠を引いたあとの、AWS の請求額 |
| 無効な段 | 生成側（負荷をかける側）の上限に当たり、関数の能力を測れなかった段。結果から除く |
| 下限値 | 生成側の上限で頭打ちになったため、本来はもっと大きいはずの値 |
| 版（`build`） | 関数のコードを最後に変えたコミット。応答に載り、全ての応答が同じ版であることを確かめる |
